第十一章：异常处理

难度：高级 预计学习时间：1 周 前置知识：函数、文件操作

异常处理是编写健壮程序的关键。Python 用 try-except 结构捕获和处理异常，让程序在遇到错误时优雅地处理，而不是直接崩溃。

前端 JS/TS 类比

Python 的 try-except 对应 JS 的 try-catch，结构几乎一一对应：Python 的 except = JS 的 catch，finally 两边都一样，else 是 Python 独有（无异常时执行）。Python 按异常类型捕获，JS 按条件判断 e instanceof。

JavaScript 
// JS 写法
try {
  JSON.parse(badJson);
} catch (e) {
  if (e instanceof SyntaxError) console.log("JSON 格式错误");
} finally {
  cleanup();
}

try-except 结构

Python
# 基本结构
try:
    num = int(input("输入数字: "))
    print(f"100 / {num} = {100 / num}")
except ValueError:
    print("输入的不是有效数字")
except ZeroDivisionError:
    print("不能除以零")

# 完整结构: try-except-else-finally
try:
    f = open("data.txt", "r")
    content = f.read()
except FileNotFoundError:
    print("文件不存在")
else:
    print(content)  # 无异常时执行
finally:
    print("清理资源")  # 总会执行
前端 JS/TS 类比

Python 的 else 块是 JS 没有的 —— 它只在 try 块没有抛出异常时执行。在 JS 中你通常会把"成功逻辑"直接写在 try 块末尾，但这有个问题：如果成功逻辑本身抛错，会被同一个 catch 捕获，难以区分。Python 的 else 完美解决了这个问题。

捕获多种异常

Python
# 捕获多种异常类型 (元组形式)
try:
    value = int("abc")
except (ValueError, TypeError) as e:
    print(f"类型错误: {e}")

# 获取异常信息
try:
    1 / 0
except ZeroDivisionError as e:
    print(f"异常类型: {type(e).__name__}")  # ZeroDivisionError
    print(f"异常信息: {e}")              # division by zero

# 捕获所有异常 (不推荐，但要知道)
try:
    result = risky_operation()
except Exception as e:
    print(f"发生错误: {e}")
    import traceback
    traceback.print_exc()  # 打印完整堆栈
注意

永远不要用裸 except:（不带异常类型），它会捕获包括 KeyboardInterrupt 在内的所有异常，导致 Ctrl+C 都无法中断程序。至少用 except Exception:。

自定义异常类

Python
# 自定义异常 — 继承 Exception
class InsufficientFundsError(Exception):
    """余额不足异常"""
    def __init__(self, balance, amount):
        self.balance = balance
        self.amount = amount
        self.deficit = amount - balance
        super().__init__(
            f"余额不足: 需要 {amount}, 仅有 {balance}, 差 {self.deficit}"
        )

# 使用自定义异常
class Account:
    def __init__(self, balance):
        self.balance = balance
    
    def withdraw(self, amount):
        if amount > self.balance:
            raise InsufficientFundsError(self.balance, amount)
        self.balance -= amount
        return self.balance

# 捕获自定义异常
acc = Account(100)
try:
    acc.withdraw(150)
except InsufficientFundsError as e:
    print(e)              # 余额不足: 需要 150, 仅有 100, 差 50
    print(f"差额: {e.deficit}")  # 访问自定义属性
前端 JS/TS 类比

Python 自定义异常继承 Exception，对应 JS 中继承 Error 类。TypeScript 中你可以这样定义带类型的自定义错误：

JavaScript 
class InsufficientFundsError extends Error {
  balance: number;
  amount: number;
  constructor(balance: number, amount: number) {
    super(`余额不足: 需要 ${amount}`);
    this.name = "InsufficientFundsError";
    this.balance = balance;
    this.amount = amount;
  }
}

throw new InsufficientFundsError(100, 150);

注意：Python 异常用 raise 抛出，JS/TS 用 throw。Python 自定义异常自动支持 except ... as e 解构，JS 需要 e instanceof 判断。

raise 与异常链

Python
# raise — 主动抛出异常
def set_age(age):
    if not isinstance(age, int):
        raise TypeError("年龄必须是整数")
    if age < 0 or age > 150:
        raise ValueError(f"年龄 {age} 不合理")
    return age

# 异常链 — raise ... from
def load_config(path):
    try:
        with open(path) as f:
            import json
            return json.load(f)
    except FileNotFoundError as e:
        # 重新抛出为更上层的异常，保留原始异常链
        raise RuntimeError("配置加载失败") from e

# 主动抑制异常链 (raise from None)
try:
    int("abc")
except ValueError:
    raise MyError("处理失败") from None  # 不显示原始异常

异常处理最佳实践

Python
# ❌ 错误：捕获过宽，吞掉异常
try:
    do_something()
except:
    pass  # 永远不要这样做！

# ✅ 正确：捕获具体异常，记录日志
import logging
logger = logging.getLogger(__name__)

try:
    do_something()
except SpecificError as e:
    logger.exception("操作失败")  # 自动记录堆栈
    raise  # 重新抛出，让上层处理

# EAFP 原则 — "请求宽恕比许可容易"
# Python 风格优先用异常而非预先检查

# ❌ LBYL 风格 (Look Before You Leap)
if "key" in data:
    value = data["key"]
else:
    value = None

# ✅ EAFP 风格 (Pythonic)
try:
    value = data["key"]
except KeyError:
    value = None
前端 JS/TS 类比

Python 的 EAFP（请求宽恕比许可容易）哲学与 JS 风格不同。JS/TS 前端开发更倾向 LBYL（先检查再执行），因为 try-catch 在 V8 中性能开销较大，且 async/await 的错误处理已经够复杂。但 Python 中 EAFP 是推荐风格，异常处理开销很小。在 TS 中，你可以用类型守卫替代异常：

JavaScript 
// TS 用类型守卫 (LBYL 风格)
function getValue(data: unknown): string | null {
  if (typeof data === "object" && data !== null && "key" in data) {
    return String((data as any).key);
  }
  return null;
}

调试技巧

写出能跑的代码只是第一步，定位问题才是日常大头。Python 提供从最朴素到最专业的多种调试手段：临时用 print 输出中间值、用 logging 按级别记录日志、以及用 pdb 进行交互式单步调试。

Python
# 1) print 大法 — 快速但临时
def process(items):
    print("items:", items)   # 临时查看
    return [x * 2 for x in items]

# 2) logging 分级 — 可长期保留、按级别过滤
import logging
logging.basicConfig(level=logging.DEBUG)
logging.debug("调试信息")
logging.info("一般信息")
logging.warning("警告")
logging.error("错误")

# 3) pdb 交互调试 — 在问题处停下，逐行检查
def buggy(x, y):
    import pdb; pdb.set_trace()   # 程序会在这里暂停
    return x / y                  # 可在提示符下查看 x、y
调试建议

pdb.set_trace() 暂停后，可用 n（下一行）、s（单步进入）、c（继续）、p 变量名（打印变量）来探查。Python 3.7+ 也可用内置的 breakpoint() 代替。

前端 JS/TS 类比

Python 的 pdb.set_trace() 对应浏览器的 debugger 语句或直接在 Chrome DevTools 里打断点；print 则对应 console.log。区别是 Python 没有浏览器那样开箱即用的可视化调试器，pdb 是命令行交互式。

JavaScript
// 浏览器中加断点（类似 pdb.set_trace()）
function buggy(x, y) {
  debugger;                 // DevTools 会在此暂停
  return x / y;
}
console.log("调试信息");     // 类似 print

assert 与异常处理

assert 用于开发期校验「绝不该发生」的内部前提；而面向用户的输入校验、可预期的外部错误，应当用 raise 抛出明确的异常。两者使用场景不同：assert 可被 python -O 优化开关整体关闭，绝不能依赖它来做正式校验。

Python
# assert — 开发期自检，可被 -O 关闭
def divide(a, b):
    assert b != 0, "除数不能为 0"
    return a / b

# 正式校验 — 用 raise 抛明确异常
def set_age(age):
    if not isinstance(age, int):
        raise TypeError("年龄必须是整数")
    if age < 0:
        raise ValueError("年龄不能为负")
    return age

# assert 在优化模式下会被跳过（不要依赖它做校验）
import sys
print(sys.flags.optimize)   # 1 表示 -O 已开启，assert 不执行
注意

不要把 assert 当异常处理用。用 python -O 或 PYTHONOPTIMIZE=1 运行程序时，所有 assert 语句会被直接删除，依赖它的校验逻辑将失效。

练习建议 动手实践

  1. 健壮的计算器 — 改造之前的计算器，用异常处理所有可能的错误：非法输入、除以零、运算符错误。
  2. 配置文件加载器 — 读取 JSON 配置文件，处理文件不存在、JSON 格式错误、必需字段缺失等异常，定义自定义异常类。
  3. 用户注册系统 — 实现注册功能，自定义 UsernameExistsError、WeakPasswordError 等异常类。
  4. 批量数据处理 — 处理一批数据，单条出错不影响整体，记录错误日志并继续处理后续数据。
