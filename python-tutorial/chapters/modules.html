第八章：模块与包管理

难度：进阶 预计学习时间：1 周 前置知识：函数基础

当程序越来越长，把所有代码塞进一个文件既难维护又容易出错。Python 用「模块」和「包」来组织代码，再配合 pip 与虚拟环境管理第三方依赖。本章带你掌握工程化开发中最关键的几项技能。

模块基础

在 Python 中，一个 .py 文件就是一个模块。模块名就是文件名（不含 .py）。通过 import 可以把别的模块引入当前文件，从而复用其中的函数、类和变量。解释器在第一次 import 时执行模块顶层代码，之后再次导入不会重复执行。

Python 
# greeting.py —— 一个最简单的模块
def greet(name):
    return f"你好, {name}!"

pi = 3.14159

# 惯用法：只有直接运行本文件时，__name__ 才等于 "__main__"
if __name__ == "__main__":
    print(greet("Python"))
    print("这是模块内部测试代码，被 import 时不会执行")


# 另一个文件中：模块顶层代码只执行一次
import greeting          # 打印一次问候
import greeting          # 第二次导入，什么也不会打印
print(greeting.pi)       # 3.14159
提示

把可执行逻辑放进 if __name__ == "__main__": 块，是 Python 社区的标准写法。这样模块既能作为脚本直接运行做自测，又能被安全地 import 而不触发副作用。

前端 JS/TS 类比：模块与导出

Python 的 .py 文件天然就是模块，用 import 引入；这对应 JS 的 ES Module：一个 .js 文件就是一个模块，通过 export 暴露接口、import 引入。两者都遵循「一个文件一个模块、用导入复用」的思想。

JavaScript 
// mathUtils.js —— ES Module
export const pi = 3.14159;
export function greet(name) {
  return `你好, ${name}!`;
}

// 入口文件 main.js
import { greet } from "./mathUtils.js";
console.log(greet("JavaScript"));  // 模块只会被求值一次

导入方式

Python 提供多种导入写法，满足不同粒度的复用需求。核心原则：明确比隐式更好，尽量导入需要的名字，而不是把整个命名空间搬进来。

Python 
# 方式一：整体导入，使用时加前缀
import math
print(math.sqrt(16))     # 4.0

# 方式二：导入指定成员，直接使用名字
from math import pi, sin
print(pi)                # 3.141592653589793

# 方式三：使用别名，避免名字冲突或简化长名
import numpy as np
import datetime as dt

# 不推荐：通配符导入会污染命名空间，难追踪来源
from math import *       # 可能悄悄覆盖已有名称
注意

from xxx import * 会把模块里所有公开名字（以及 __all__ 列出的名字）一股脑塞进当前作用域，既容易命名冲突，又让代码可读性变差。生产代码请避免使用。

前端 JS/TS 类比：命名导入

Python 的 from math import pi, sin 对应 JS 的命名导入 import { pi, sin } from "mathjs"；import math 对应 import * as math 的命名空间导入。

JavaScript 
// 命名导入，对应 Python 的 from math import pi, sin
import { pi, sin } from "mathjs";

// 命名空间导入，对应 Python 的 import math
import * as math from "mathjs";
console.log(math.sqrt(16));  // 4

// 默认导入 + 别名
import { default as _ } from "lodash";

包与 __init__

当模块变多，可以用「包」把相关模块组织进目录。一个包含 __init__.py 文件的目录就是一个包。__init__.py 本身也是模块（包的名字即它），常用来做包级初始化。__all__ 则控制 from 包 import * 时导出的内容。

Python 
# 包结构示例：
# mymath/
#   __init__.py
#   basic.py
#   advanced.py

# mymath/__init__.py —— 定义包对外导出的名字
__all__ = ["add", "subtract", "power"]

from .basic import add, subtract
from .advanced import power

# mymath/basic.py
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b

# mymath/advanced.py —— 相对导入：. 表示当前包
from .basic import add

def power(base, exp):
    result = 1
    for _ in range(exp):
        result = add(result * base if result != 1 else base, 0)
    return base ** exp
提示

相对导入用 . 表示当前包、.. 表示上一级包，只能在包内部使用，且包要通过 import 方式加载（不能直接作为脚本运行）。

前端 JS/TS 类比：目录模块与 package.json

Python 的「包目录 + __init__.py」对应 Node.js 的「目录 + package.json」。__init__.py 的 __all__ 相当于 package.json 的 exports 字段，声明对外暴露的入口。

JavaScript 
// Node.js 中一个目录 + package.json 即是一个"包"
// package.json
{
  "name": "mymath",
  "main": "index.js",
  "exports": {
    ".": "./index.js"
  }
}

// index.js —— 聚合导出，等价于 Python 的 __init__.py
export { add, subtract } from "./basic.js";
export { power } from "./advanced.js";

pip 与依赖

pip 是 Python 的包安装器。它从 PyPI（Python 包索引）下载并安装第三方库。把项目的依赖固化到 requirements.txt，可以让别人一键复现你的运行环境。

Bash 
# 安装最新版包
pip install requests

# 安装指定版本
pip install requests==2.31.0

# 导出当前环境所有依赖到 requirements.txt
pip freeze > requirements.txt

# 根据清单安装依赖
pip install -r requirements.txt
前端 JS/TS 类比：npm install 与 package.json

pip install 对应 npm install，requirements.txt 对应 package.json 的依赖清单。两者都解决了「记录并复现第三方依赖」的问题。

JavaScript 
// package.json —— npm 的依赖清单，等价于 Python 的 requirements.txt
{
  "name": "my-project",
  "dependencies": {
    "lodash": "^4.17.21",
    "express": "^4.18.2"
  },
  "devDependencies": {
    "jest": "^29.0.0"
  }
}

虚拟环境

不同项目可能需要同一库的不同版本。虚拟环境为每个项目创建隔离的 Python 运行空间，避免全局安装互相污染。python -m venv 是官方推荐工具。

Bash 
# 在项目目录下创建虚拟环境
python -m venv .venv

# 激活虚拟环境（Windows）
.venv\Scripts\activate

# 激活虚拟环境（macOS / Linux）
source .venv/bin/activate

# 安装依赖只会影响当前环境
pip install requests

# 退出虚拟环境
deactivate
前端 JS/TS 类比：node_modules 与 nvm

Python 的虚拟环境隔离整套解释器与依赖，类似于 Node 项目用 node_modules 隔离依赖、用 nvm 切换 Node 版本（等价于 pyenv / venv 的组合）。

JavaScript 
// Node 默认把依赖装进项目下的 node_modules/
// 等价于 Python venv 的"每个项目独立环境"
const path = require("path");
console.log(path.resolve("node_modules"));  // 项目级依赖目录

__future__ 新特性兼容

__future__ 模块让你在当前 Python 版本中提前使用将在未来成为默认行为的新特性。最常见的用法是 from __future__ import annotations，它让类型注解延迟求值，从而支持前向引用、减少运行时开销。

Python 
# 让类型注解延迟求值（Python 3.7+ 推荐）
from __future__ import annotations

def add(a: int, b: int) -> int:
    return a + b

# annotations 开启后，注解不会立即求值，支持前向引用
class Node:
    def add_child(self, node: "Node") -> None:
        ...

# 历史上：从 Python 2 平滑迁移到 Python 3 的除法语义
from __future__ import division
print(1 / 2)    # 0.5（在 Python 2 中原本是 0）

练习建议 动手实践

  1. 写一个计算器模块 — 创建 calculator.py，实现加、减、乘、除四个函数，并在 if __name__ == "__main__": 块中写一段自测代码，验证函数正确性。
  2. 组织成包并控制导出 — 把多个功能模块放进一个包（带 __init__.py），用 __all__ 约束 from 包 import * 只导出指定名字。
  3. 用 venv 建立项目环境 — 新建目录，用 python -m venv 创建并激活虚拟环境，安装一个第三方库（如 requests）验证隔离效果。
  4. 导出依赖清单 — 在上一步的虚拟环境中执行 pip freeze > requirements.txt，然后把该文件交给他人，验证对方能一键复现环境。
