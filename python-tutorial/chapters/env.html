第一章：环境搭建与第一个程序

难度：入门 预计学习时间：1 周 前置知识：无

万事开头难，但 Python 的环境搭建其实非常友好。本章将带你安装 Python 解释器、认识交互式编程环境 REPL、写出并运行人生中第一个 Python 程序，以及选择一款顺手的编辑器。更重要的是，你会理解为什么需要"虚拟环境"——这是绝大多数初学者踩坑的地方。跟着做完练习，你就能拥有一套干净、可复用的 Python 开发环境。

安装解释器并验证 理解 REPL 即时反馈 用 .py 文件写程序 配置编辑器 + 虚拟环境

安装 Python

Python 是一门高级、解释型、跨平台的编程语言：一行代码写完后，由解释器逐行翻译成机器指令执行，而不是像 C/C++ 那样先整体编译成二进制。这种"边解释边运行"的特性让开发调试极其高效，也带来了极其丰富的第三方库生态——它能写脚本自动化处理文件、做 Web 开发、数据分析、人工智能。无论你用 Windows、macOS 还是 Linux，都能轻松安装。

从零安装：4 个步骤

  • 确认是否已安装

    打开终端输入 python3 --version。若显示版本号（如 3.12.x）即可跳过安装；若提示"command not found"，继续下一步。

  • 下载并安装

    Windows 前往 python.org 下载安装包，务必勾选 "Add Python to PATH"；macOS 推荐 brew install python；Linux 用 sudo apt install python3。

  • 验证安装

    重新打开终端运行 python3 --version，确认输出正确的版本号，说明解释器已就绪。

  • 建立项目隔离环境（关键一步）

    用 python3 -m venv .venv 为当前项目创建独立环境，避免不同项目的依赖互相污染（详见下方场景）。

Bash
# 验证安装是否成功（任选其一）
python --version
python3 --version
# 输出类似: Python 3.12.1

# 查看 pip（包管理器）版本
pip3 --version
提示

很多系统同时装有 Python 2 和 Python 3。python 命令可能指向旧版 Python 2（已于 2020 年停止维护），而 python3 明确指向 Python 3。本教程全部基于 Python 3，遇到命令不存在时请用 python3 代替。

实际场景：用虚拟环境隔离两个项目

假设你有两个项目：A 需要 Django 4，B 需要 Django 5。如果都装到全局环境，后者会覆盖前者，导致 A 崩溃。虚拟环境让每个项目拥有独立的依赖副本：

Bash
# 项目 A
cd ~/projects/A
python3 -m venv .venv        # 创建隔离环境
source .venv/bin/activate    # 激活（Windows: .venv\Scripts\activate）
pip install django==4.2      # 只在 A 的环境里装 Django 4

# 另开终端做项目 B
cd ~/projects/B
python3 -m venv .venv
source .venv/bin/activate
pip install django==5.0      # B 的环境独立，互不影响

激活后终端提示符前会出现 (.venv)，此时 python/pip 都指向环境内的解释器。deactivate 可退出环境。这是 Python 工程化的第一道护城河。

示意图：全局环境 vs 虚拟环境 —— 虚拟环境为每个项目复制一份独立的 Python 与依赖，彻底避免"一个项目升级，另一个项目崩掉"的依赖地狱。

前端 JS/TS 类比：版本管理

不同项目可能需要不同 Python 版本，就像前端项目可能依赖不同 Node 版本。Node 生态用 nvm 切换版本；Python 生态用 pyenv 管理多个解释器版本，并用 venv 隔离依赖，对应前端的 npm install 装在项目本地 node_modules 的思路。

JavaScript
// 用 nvm 切换 Node 版本（对应 pyenv）
$ nvm install 18
$ nvm use 18
$ node --version   // v18.x.x

// Python 的对应思路（命令行）
$ pyenv install 3.12.1
$ pyenv local 3.12.1
$ python --version // 3.12.1

Python 解释器

安装完成后，在终端直接输入 python3 即可进入交互式解释器 REPL（Read-Eval-Print Loop，读取—求值—打印—循环）。提示符 >>> 表示等待你输入代码，回车后立即得到结果——非常适合做快速计算、试 API、验证想法，被称为"Python 的扑克牌"，随手就能玩。

Bash
$ python3
Python 3.12.1 (main, Dec  1 2023) [...]
>>> 1 + 1
2
>>> name = "Python"
>>> print(name)
Python
>>> exit()      # 退出解释器（也可按 Ctrl+D）
提示

REPL 里可以用 _（单下划线）获取上一次表达式的结果；用 help(对象) 查看任意函数/类型的文档；用 dir(对象) 列出它的所有属性和方法，是探索未知库的神器。

实际场景：用 REPL 快速验证一个 API

在写正式代码前，先用 REPL 试一下某个库的行为，避免写了一大堆才发现用错：

Python
>>> s = "  Hello  "
>>> s.strip()          # 先确认方法效果
'Hello'
>>> dir(s)             # 看看字符串还有哪些方法
['capitalize', 'center', 'count', ... 'upper', 'zfill']
>>> help(s.upper)      # 查看 upper 的文档
Help on built-in function upper: ...

REPL 是"边学边试"的最佳环境，熟练使用能极大提升调试效率。

示意图：REPL 的工作循环 —— 不断"读取输入、求值、打印结果"，直到退出。它让代码反馈即时可见。

注意

REPL 里写多行逻辑（如函数、循环）时，缩进要手动对齐，容易出错。它更适合探索和学习，真正的项目请用 .py 文件编写。退出 REPL：输入 exit() 或按 Ctrl+D（macOS/Linux），Windows 可用 Ctrl+Z 回车。

第一个程序

真正的程序写在文件里。打开任意编辑器，新建文件 hello.py，写入一行打印语句，保存后在终端运行。.py 后缀告诉系统这是 Python 源码，解释器会从头到尾执行其中的语句。

Python
# hello.py
print("Hello, World!")
Bash
# 在 hello.py 所在目录运行
python3 hello.py
# 输出: Hello, World!
实际场景：给脚本加"可直接运行"的 shebang

在 macOS/Linux 下，给脚本首行加 #!/usr/bin/env python3 并用 chmod +x 授权后，就能像命令一样双击/直接运行，常用于自动化脚本：

Python
#!/usr/bin/env python3
# backup.py — 一键备份脚本
import shutil, datetime
today = datetime.date.today()
shutil.make_archive(f"backup_{today}", "zip", "mydata")
print("备份完成:", f"backup_{today}.zip")
Bash
chmod +x backup.py
./backup.py     # 直接运行，无需显式敲 python3
提示

Python 文件名推荐全小写、单词用下划线连接，并以 .py 为后缀，例如 my_first_script.py。避免使用中文、空格和连字符，也不要与标准库模块同名（如不要命名为 random.py），否则可能覆盖内置模块导致报错。

编辑器选择

合适的工具能大幅提升效率。编辑器/IDE 不仅能高亮语法，还提供智能补全、跳转定义、断点调试、一键运行——把"写代码→运行→看错→改"的循环压缩到最短。

  • VS Code：免费、轻量、插件丰富。安装官方 Python 扩展（Microsoft 出品）后，获得语法高亮、智能补全、断点调试和一键运行。在文件上右键"在终端中运行 Python 文件"即可执行。
  • PyCharm：专业 Python IDE，开箱即用，自带虚拟环境管理、强大的重构与调试功能。社区版免费，适合中大型项目。
  • Jupyter Notebook：以"单元格"为单位交互式运行，特别适合数据分析、教学演示，能边写文档边跑代码边看图。
实际场景：用 VS Code 调试一段报错的代码

假设代码在某行抛异常，与其反复加 print 猜测，不如在行号左侧点一下加断点，按 F5 启动调试，逐行观察变量值：

Python
def avg(numbers):
    total = 0
    for n in numbers:
        total += n
    return total / len(numbers)   # 若 numbers 为空会 ZeroDivisionError

print(avg([]))   # 触发异常 → 在调试器里观察 numbers 的值

调试器能停在断点、查看调用栈、单步执行，比盲目 print 高效得多。这是把"环境"用好的关键一步。

配置完成后，建议打开编辑器内置终端，验证 python3 hello.py 能正常输出。把终端和编辑器放在一个窗口里，就能边写边运行，体验非常流畅。

输入与输出

程序需要与用户或外部环境交换信息。print() 把内容输出到屏幕（标准输出），input() 接收用户从键盘输入的一行文本（返回字符串）。这里先简单体验，下一章"基础语法"会详细讲解格式化与编码。

Python
# 输出
print("请输入你的名字：")

# 输入（括号内是提示语，返回的是字符串）
name = input("你的名字: ")
print("你好, " + name + "!")

# print 可同时输出多个值，默认用空格分隔
print("欢迎来到", name, "的 Python 之旅")
实际场景：交互式命令行小工具

把输入、计算、输出串起来，就是一个能实际使用的命令行工具（例如单位换算）：

Python
print("=== 摄氏 → 华氏 换算器 ===")
c = float(input("请输入摄氏温度: "))
f = c * 9 / 5 + 32
print(f"{c}°C = {f:.1f}°F")   # 例如 25.0°C = 77.0°F

这里 input() 返回字符串，必须用 float() 转换才能做数学运算——这是初学者最常见的类型错误来源，务必牢记。

本章核心要点
  • Python 是解释型语言，靠解释器逐行执行，开发与调试高效。
  • 命令用 python3（避免与 Python 2 混淆）；pip3 是包管理器。
  • 虚拟环境 venv 是工程化基础：每个项目隔离依赖，告别依赖冲突。
  • REPL 适合即时试错与探索；正式项目写在 .py 文件里。
  • print() 输出、input() 输入（返回字符串，需转换类型）。
  • 选 VS Code/PyCharm 并学会用调试器，能成倍提升效率。

练习建议 动手实践

  1. 安装并验证 — 在你的操作系统上安装 Python，运行 python3 --version 确认版本，并创建 hello.py 输出 Hello, World!。
  2. 配置虚拟环境 — 新建一个项目目录，创建并激活 venv，在环境内安装一个第三方库（如 requests），确认 pip list 中能看到它。
  3. 个人介绍程序 — 用 print() 输出你的姓名、年龄、所在城市等至少 3 条信息。
  4. 小问答程序 — 用 input() 询问用户喜欢的编程语言，再把回答原样打印出来，并加上一句"原来你喜欢 XX！"。
  5. 调试初体验 — 在 VS Code/PyCharm 中给一个会报错的脚本加断点，用调试器观察变量，定位问题。
