第二十三章：部署上线与 CI/CD

难度：进阶 预计学习时间：1 周 前置知识：Web 开发、API 设计

应用在本地跑通只是第一步，真正交付要让全世界访问得到。本章带你把待办应用部署到服务器：用 Gunicorn 替代开发服务器、用 Docker 打包环境、用 Nginx 做反向代理、用 GitHub Actions 实现推送即部署。让"代码 → 线上"这条链路自动化、可复现。

WSGI 生产服务器 Docker 容器化 Nginx 反向代理 CI/CD 自动部署

WSGI 与 Gunicorn

Flask 自带的 app.run() 是单线程开发服务器，无法承受并发，且开了 debug 不安全。生产用 WSGI 服务器如 Gunicorn，它能预生成多个 worker 进程并发处理请求，更稳定高效。

Bash
pip install gunicorn

# 启动：模块名:应用实例，4 个 worker
gunicorn -w 4 -b 0.0.0.0:8000 "app:create_app()"
# -w worker 数（一般 CPU 核数 × 2 + 1）
# -b 监听地址端口
# --daemon 后台运行

示意图：典型部署架构 —— Nginx 在前接收请求并分发静态资源，转给 Gunicorn 的多个 worker，worker 内跑 Flask 应用，多进程并发扛住流量。

配置与环境变量

生产与开发的配置不同（数据库地址、密钥、调试开关）。不要把生产密钥写进代码，应从环境变量读取，遵循"十二要素应用"规范。

Python
import os

def create_app():
    app = Flask(__name__)
    app.config["SECRET_KEY"] = os.environ["SECRET_KEY"]            # 必须从环境读
    app.config["SQLALCHEMY_DATABASE_URI"] = os.environ.get(
        "DATABASE_URL", "sqlite:///todo.db")                       # 有默认值
    app.config["DEBUG"] = False                                     # 生产关闭
    return app
Bash
# 用 .env 文件管理（不入版本库）
echo ".env" >> .gitignore

# .env 内容
# SECRET_KEY=production-super-secret
# DATABASE_URL=postgresql://user:pwd@dbhost/todo

# 启动时加载（用 python-dotenv 或 shell）
export $(grep -v '^#' .env | xargs)
gunicorn -w 4 -b 0.0.0.0:8000 "app:create_app()"

Docker 容器化

Docker 把应用连同依赖、环境一起打包成镜像，保证"在我电脑能跑，在你服务器也能跑"，消除环境差异。这是现代部署的事实标准。

Dockerfile
# Dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["gunicorn", "-w", "4", "-b", "0.0.0.0:8000", "app:create_app()"]
Bash
# 构建镜像
docker build -t todo-app:latest .

# 运行容器，把 8000 映射出来，并注入环境变量
docker run -d -p 8000:8000 --env-file .env --name todo todo-app:latest

# 查看日志 / 停止
docker logs todo
docker stop todo
提示

用 .dockerignore 排除 .venv、__pycache__、.git，避免把无用文件打进镜像，缩小体积、加快构建。镜像分层缓存：把变化少的 requirements.txt 拷贝放在前面，依赖不变时可复用缓存层。

Nginx 反向代理

Nginx 作为反向代理放在 Gunicorn 前：处理 HTTPS 证书、服务静态文件（CSS/JS/图片）、做负载均衡与限流，让 Gunicorn 专注动态请求。

Nginx
# /etc/nginx/sites-available/todo
server {
    listen 80;
    server_name todo.example.com;

    # 静态资源直接由 Nginx 提供，更快
    location /static/ {
        alias /app/static/;
    }

    # 其余请求转给 Gunicorn
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
项目案例：一条龙部署到 Linux 服务器

假设已有一台云服务器，完整流程：

Bash
# 1. 服务器装 Docker 与 Nginx
sudo apt update && sudo apt install -y docker.io nginx

# 2. 拉镜像/构建并跑容器
docker run -d -p 8000:8000 --env-file .env --name todo todo-app

# 3. 配置 Nginx 反代（见上），重载
sudo nginx -t && sudo systemctl reload nginx

# 4. 用 certbot 申请免费 HTTPS 证书
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d todo.example.com

完成后浏览器访问 https://todo.example.com 即是线上应用。

CI/CD 自动化

手动部署易错且不可复现。CI/CD（持续集成/持续部署）让"提交代码 → 自动测试 → 自动构建镜像 → 自动部署"一条龙完成。GitHub Actions 是入门友好的选择。

YAML
# .github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main]          # 推到 main 触发

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r requirements.txt
      - run: pytest            # 先跑测试，失败则中止
      - name: Build & push image
        run: |
          docker build -t myrepo/todo-app:latest .
          docker push myrepo/todo-app:latest
      - name: Deploy to server
        run: ssh user@server "docker pull myrepo/todo-app:latest && docker stop todo && docker rm todo && docker run -d -p 8000:8000 --env-file .env --name todo myrepo/todo-app:latest"
前端 JS/TS 类比：前端部署

前端部署思路类似：构建产物（npm run build → dist/）上传到 CDN 或静态托管，CI 里跑 lint/test/build。区别在于前端是静态资源，后端是常驻进程，需要 Gunicorn 这类应用服务器。

JavaScript
// 前端 CI 常见步骤（对照后端）
// - npm ci          安装依赖
// - npm run lint     代码检查
// - npm test         单测
// - npm run build    构建 dist/
// - 上传到 OSS/CDN
本章核心要点
  • 生产用 Gunicorn（多 worker）替代开发服务器，关闭 debug。
  • 配置从环境变量读取，密钥不入代码库。
  • Docker 把应用+依赖打包成镜像，环境一致、可复现。
  • Nginx 反向代理：HTTPS、静态资源、负载均衡。
  • CI/CD 自动化：推送 → 测试 → 构建 → 部署，减少人为错误。

练习建议 动手实践

  1. Gunicorn 启动 — 用 Gunicorn 跑待办应用，压测对比与开发服务器的差异。
  2. Docker 化 — 写 Dockerfile，构建镜像并在容器里运行。
  3. Nginx + HTTPS — 配置 Nginx 反代，用 certbot 上 HTTPS。
  4. CI 流水线 — 写 GitHub Actions，push 后自动跑测试并构建镜像。
