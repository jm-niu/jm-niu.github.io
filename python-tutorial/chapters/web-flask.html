第十九章：Web 开发实战（Flask 入门）

难度：进阶 预计学习时间：1-2 周 前置知识：函数、模块、面向对象、异常处理

从本章起，我们离开"命令行脚本"的世界，进入Web 开发——用 Python 写出能在浏览器里访问的应用。本章以轻量级框架 Flask 为例，带你从零搭建一个真实项目：初始化工程、设计路由、渲染页面模板、处理用户请求与表单。学完本章你就能独立做出一个可访问的"待办清单"网站雏形。

理解 HTTP 请求/响应 用 Flask 初始化项目 设计路由 + 模板 处理表单与重定向

Web 与 Flask 概览

Web 应用的本质是"请求—响应"循环：浏览器发起 HTTP 请求，服务器接收后调用对应处理函数，生成响应（HTML 页面或 JSON）返回浏览器。框架帮你屏蔽了"监听端口、解析 HTTP、拼接响应"等繁琐细节，让你专注业务逻辑。

Python 主流 Web 框架各有定位：

  • Flask：轻量、灵活、"微框架"，只提供路由与请求响应，其余按需扩展，适合学习与中小项目。
  • Django：大而全，自带 ORM、后台、认证、模板，适合快速搭建内容型网站。
  • FastAPI：现代、高性能，基于类型注解自动生成文档，适合构建 API 服务。

本教程选用 Flask，因为它结构简单、概念清晰，是理解 Web 原理的最佳起点。

示意图：Web 应用的请求—响应循环 —— Flask 的核心工作就是"把 URL 路由到对应视图函数"，再把函数返回值作为 HTTP 响应送回浏览器。

前端 JS/TS 类比：前后端协作

如果你写过 Vue/React，那前端是"在浏览器里跑的 SPA"，通过 fetch/axios 向后端发请求。Flask 就是接收这些请求的后端。前端负责交互与渲染，后端负责数据与业务。本章我们先让 Flask 直接返回完整 HTML 页面（传统 SSR），后面 API 章节再讲前后端分离。

JavaScript
// 前端发起请求（对应 Flask 路由接收）
fetch("/api/todos")
  .then(r => r.json())
  .then(data => console.log(data));

项目初始化

遵循第 1 章学到的虚拟环境规范，先把工程骨架搭起来。一个清晰的目录结构是可维护项目的起点。

从零搭建：4 个步骤

  • 创建项目目录与虚拟环境

    建文件夹、进入、用 venv 创建隔离环境并激活，确保依赖不污染全局。

  • 安装 Flask

    pip install flask，并把依赖固化到 requirements.txt 以便复现。

  • 规划目录结构

    分出 app.py（入口）、templates/（模板）、static/（静态资源），让职责清晰。

  • 写最小可运行应用

    用 @app.route("/") 定义首页，app.run() 启动开发服务器，浏览器访问验证。

Bash
# 1. 建目录与虚拟环境
mkdir todo_web && cd todo_web
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate

# 2. 安装 Flask 并固化依赖
pip install flask
pip freeze > requirements.txt

# 3. 目录结构
# todo_web/
# ├── app.py          # 应用入口
# ├── templates/      # Jinja2 模板
# │   └── index.html
# └── static/         # css/js/图片
#     └── style.css
Python
# app.py — 最小可运行应用
from flask import Flask

app = Flask(__name__)          # 创建应用实例

@app.route("/")                 # 把根路径绑定到下面函数
def index():
    return "Hello, Flask! 🐍"

if __name__ == "__main__":
    app.run(debug=True)         # 开启调试，改代码自动重启
Bash
python app.py
# 控制台显示: Running on http://127.0.0.1:5000
# 浏览器打开该地址即可看到 Hello, Flask!
注意

debug=True 仅用于开发，它会暴露调试器、允许任意代码执行，绝对不能用于生产。生产部署用专门的 WSGI 服务器（如 Gunicorn），见部署章。

路由设计

路由就是"URL → 处理函数"的映射表"。Flask 用装饰器 @app.route(路径) 声明路由，简洁直观。路径里可用 <类型:变量> 捕获动态参数。

Python
from flask import Flask

app = Flask(__name__)

# 静态路由
@app.route("/")
def home():
    return "首页"

@app.route("/about")
def about():
    return "关于我们"

# 动态路由 — 捕获路径参数
@app.route("/user/<username>")
def user_profile(username):
    return f"用户：{username}"

# 指定类型转换器
@app.route("/post/<int:post_id>")
def show_post(post_id):
    return f"文章 #{post_id}"

# 限定 HTTP 方法
@app.route("/login", methods=["GET", "POST"])
def login():
    return "登录页（GET 展示 / POST 提交）"
提示

RESTful 风格中，同一个 URL 用不同 HTTP 方法表达不同动作：GET /todos 列表、POST /todos 新建、DELETE /todos/1 删除。这与"一个动作一个 URL"的传统风格不同，更符合资源语义（详见 API 设计章）。

模板渲染 (Jinja2)

直接在 Python 里拼 HTML 字符串既难写又难维护。Flask 内置 Jinja2 模板引擎，让你把 HTML 放在 templates/ 目录，用 {{ 变量 }} 插值、{% 控制 %} 做逻辑，实现数据与视图分离。

Python
from flask import Flask, render_template

app = Flask(__name__)

@app.route("/greet/<name>")
def greet(name):
    # render_template 会去 templates/ 目录找模板并渲染
    return render_template("greet.html", name=name, count=3)
HTML
<!-- templates/greet.html -->
<!DOCTYPE html>
<html>
<body>
  <h1>你好，{{ name }}！</h1>
  <ul>
    {% for i in range(count) %}
      <li>第 {{ i + 1 }} 条</li>
    {% endfor %}
  </ul>
  {% if count == 0 %}
    <p>暂无数据</p>
  {% endif %}
</body>
</html>
前端 JS/TS 类比：模板引擎

Jinja2 的 {{ }}/{% %} 对应 Vue 的 {{ }} 插值与 v-for/v-if 指令，或 React 的 JSX 表达式。区别在于 Jinja2 在服务器端渲染好 HTML 再发给浏览器，而 Vue/React 通常在客户端渲染（或 SSR）。两者可结合：Flask 提供 API，前端框架渲染界面。

JavaScript
// Vue 模板写法（对应 Jinja2 的思路）
<template>
  <ul>
    <li v-for="(item, i) in items" :key="i">第 {{ i + 1 }} 条</li>
  </ul>
</template>

请求与响应

视图函数通过全局对象 request 读取请求数据（查询参数、表单、JSON body、头部），通过返回值或 Response/jsonify 控制响应。

Python
from flask import Flask, request, jsonify, redirect, url_for

app = Flask(__name__)

@app.route("/search")
def search():
    # 读取查询参数 ?q=python&page=2
    q = request.args.get("q", "")
    page = request.args.get("page", 1, type=int)
    return f"搜索：{q}，第 {page} 页"

@app.route("/api/data", methods=["POST"])
def api_data():
    # 读取 JSON 请求体
    data = request.get_json()
    return jsonify({"echo": data, "ok": True})   # 返回 JSON 响应

@app.route("/old")
def old():
    # 重定向到另一个路由
    return redirect(url_for("home"))
项目案例：待办清单网站（核心）

把路由、模板、请求串起来，做一个能用浏览器增删待办的小网站。本例用内存列表存数据（数据库在下一章接入）：

Python
# app.py
from flask import Flask, render_template, request, redirect, url_for

app = Flask(__name__)
todos = []                       # 暂用内存列表存储

@app.route("/")
def index():
    return render_template("index.html", todos=todos)

@app.route("/add", methods=["POST"])
def add():
    task = request.form.get("task", "").strip()
    if task:
        todos.append({"task": task, "done": False})
    return redirect(url_for("index"))     # PRG 模式：提交后重定向

@app.route("/done/<int:i>")
def done(i):
    if 0 <= i < len(todos):
        todos[i]["done"] = not todos[i]["done"]
    return redirect(url_for("index"))

@app.route("/delete/<int:i>")
def delete(i):
    if 0 <= i < len(todos):
        todos.pop(i)
    return redirect(url_for("index"))

if __name__ == "__main__":
    app.run(debug=True)
HTML
<!-- templates/index.html -->
<!DOCTYPE html>
<html>
<head><link rel="stylesheet" href="{{ url_for('static', filename='style.css') }}"></head>
<body>
  <h1>我的待办</h1>
  <form method="post" action="{{ url_for('add') }}">
    <input name="task" placeholder="输入任务" required>
    <button>添加</button>
  </form>
  <ul>
    {% for t in todos %}
    <li class="{{ 'done' if t.done else '' }}">
      {{ t.task }}
      <a href="{{ url_for('done', i=loop.index0) }}">完成</a>
      <a href="{{ url_for('delete', i=loop.index0) }}">删除</a>
    </li>
    {% endfor %}
  </ul>
</body>
</html>

启动后访问 http://127.0.0.1:5000，即可在浏览器里增删待办。这是从"脚本"到"应用"的关键一跃。

提示

表单提交后用 redirect 而非直接渲染，这叫 PRG 模式（Post/Redirect/Get），可避免用户刷新页面时重复提交。这是 Web 开发的经典最佳实践。

表单处理

表单是用户向服务器提交数据的主要方式。GET 用于查询（参数在 URL），POST 用于提交（数据在 body）。处理表单时务必做校验与清洗，防止空值、超长、注入。

Python
from flask import Flask, request, render_template

app = Flask(__name__)

@app.route("/register", methods=["GET", "POST"])
def register():
    error = None
    if request.method == "POST":
        username = request.form.get("username", "").strip()
        password = request.form.get("password", "")
        # 服务端校验（不能只靠前端 JS）
        if not username or len(username) < 3:
            error = "用户名至少 3 个字符"
        elif len(password) < 6:
            error = "密码至少 6 位"
        else:
            return "注册成功，欢迎 " + username
    # GET 或校验失败时回到表单页
    return render_template("register.html", error=error)
注意

永远不要信任前端校验。HTML 的 required、JS 校验只是体验，用户可绕过。服务端必须再做一次校验，这是安全的第一道防线（详见认证与安全章）。

本章核心要点
  • Web 应用 = "请求—响应"循环；框架屏蔽 HTTP 细节，让你专注业务。
  • Flask 用 @app.route 把 URL 绑定到视图函数，<int:id> 捕获动态参数。
  • Jinja2 模板用 {{ }} 插值、{% %} 控制流，实现数据与视图分离。
  • request 读请求数据，jsonify/redirect/render_template 控制响应。
  • 表单提交后用 PRG 重定向避免重复提交；服务端必须校验。
  • debug=True 仅限开发，生产用 Gunicorn 部署。

练习建议 动手实践

  1. 跑通最小应用 — 按步骤建项目、装 Flask、写 app.py，浏览器看到 Hello, Flask。
  2. 完成待办清单 — 复刻本章案例，实现添加/完成/删除，并加 CSS 美化已完成项。
  3. 注册表单 — 实现带服务端校验的注册页，失败时回显错误与已填用户名。
  4. 动态路由练习 — 做 /user/<name> 个人页，模板展示该用户的欢迎信息与待办。
