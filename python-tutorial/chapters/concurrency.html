第十六章：进程与线程

难度：高级 预计学习时间：1-2 周 前置知识：函数、模块基础

当单线程程序跑得不够快时，我们就需要"并发"：让多个任务看起来（或真正）同时进行。Python 提供两种最基础的并发手段——多进程与多线程。理解它们与 GIL 的关系，是写出高性能 Python 程序的关键。

多进程

每个进程有独立的内存空间和 Python 解释器，因此能绕过 GIL，真正利用多核 CPU，适合 CPU 密集型任务。Process 启动单个子进程，Pool 则管理一组进程并行处理任务。

Python 
from multiprocessing import Process, Pool

# 方式一：单个 Process
def worker(n):
    print(f"进程 {n} 开始工作")

if __name__ == "__main__":
    ps = [Process(target=worker, args=(i,)) for i in range(3)]
    for p in ps:
        p.start()
    for p in ps:
        p.join()

# 方式二：Pool 并行映射
def square(x):
    return x * x

if __name__ == "__main__":
    with Pool(4) as pool:        # 4 个工作进程
        result = pool.map(square, [1, 2, 3, 4, 5])
    print(result)               # [1, 4, 9, 16, 25]
注意

Windows 下多进程代码必须放在 if __name__ == "__main__": 里，否则子进程重复导入模块会导致无限递归启动进程。尤其在 Windows/macOS spawn 模式下尤为关键。

前端 JS/TS 类比：多进程

Node.js 是单线程的，要利用多核得用 worker_threads（线程）或 cluster（多进程）。后者为每个 CPU 核起一个独立进程，和 Python 的 multiprocessing.Pool 思路一致。

JavaScript 
// Node.js cluster：每个核一个进程
const cluster = require("cluster");
const os = require("os");

if (cluster.isPrimary) {
  os.cpus().forEach(() => cluster.fork());
} else {
  console.log(`工作进程 ${process.pid} 已启动`);
}

多线程与 GIL

线程共享同一进程的内存，创建开销小。但 CPython 有全局解释器锁（GIL）：同一时刻只有一个线程执行 Python 字节码。因此多线程在CPU 密集任务上无法真正并行，却非常适合IO 密集（网络、文件）任务——等待 IO 时 GIL 会释放给其他线程。

Python 
import threading

# 共享变量 + Lock 保护
counter = 0
lock = threading.Lock()

def add():
    global counter
    for _ in range(100000):
        with lock:              # 加锁，防止竞态条件
            counter += 1

if __name__ == "__main__":
    t1 = threading.Thread(target=add)
    t2 = threading.Thread(target=add)
    t1.start(); t2.start()
    t1.join(); t2.join()
    print(counter)             # 200000（加锁后结果正确）
注意

不加 Lock 同时修改共享变量，会因竞态条件得到错误结果。多个线程写同一份数据，必须加锁或使用线程安全的数据结构。

前端 JS/TS 类比：单线程与 Worker

JS 主线程本就是单线程、无 GIL 概念（靠事件循环）。CPU 重活要丢给 Web Worker（独立线程），与 Python 用 threading 处理 IO 等待、用多进程处理 CPU 密集，是互补的思路。

JavaScript 
// 主线程：不阻塞 UI
const worker = new Worker("heavy.js");
worker.postMessage({ data: [1, 2, 3] });
worker.onmessage = (e) => {
  console.log("结果:", e.data);
};

ThreadLocal：线程私有数据

有时我们想让每个线程拥有自己的"全局变量"，互不干扰。threading.local() 创建的对象，其属性在每个线程中都是独立副本。

Python 
import threading

# 每个线程看到的是自己的 user 属性
local_data = threading.local()

def show():
    name = getattr(local_data, "user", None)
    print(f"[{threading.current_thread().name}] user = {name}")

def worker(name):
    local_data.user = name     # 只在本线程可见
    show()

if __name__ == "__main__":
    t1 = threading.Thread(target=worker, args=("Alice",), name="T1")
    t2 = threading.Thread(target=worker, args=("Bob",), name="T2")
    t1.start(); t2.start()
    t1.join(); t2.join()
    # 输出：T1 看到 Alice，T2 看到 Bob，互不影响

进程 vs 线程：如何选型

核心判断依据是你任务的瓶颈在CPU 计算还是IO 等待，再决定用进程、线程还是协程（asyncio，见后续章节）。

Python 
# 经验法则
# CPU 密集（计算、编码、图像处理）  -> 多进程 multiprocessing
# IO 密集（网络请求、文件读写）     -> 多线程 threading 或 协程 asyncio
# 既要计算又要高并发               -> 进程池 + 协程结合

def is_cpu_bound(task):
    return task.type == "compute"

def is_io_bound(task):
    return task.type in ("network", "disk")
提示

协程（asyncio）在单线程内用事件循环实现高并发，特别适合海量 IO 连接（如爬虫、网关）。它不绕过 GIL，但比线程更轻量、无锁。

维度 多进程 多线程 协程 (asyncio)
是否绕过 GIL 是（独立解释器） 否 否（单线程内切换）
适合场景 CPU 密集 IO 密集 高并发 IO
内存开销 大（独立内存） 小（共享内存） 极小
数据共享 需队列/管道 直接共享（需加锁） 无需锁
切换成本 高 中 低

练习建议 动手实践

  1. 多线程下载 — 用 threading 并发下载多个网页（或一个文件分成几段），体会 IO 等待期间线程切换带来的提速。
  2. 多进程计算 — 用 multiprocessing.Pool 把大数列表分段求平方和，对比单进程耗时差异。
  3. Lock 示例 — 故意去掉上例中的 Lock，观察共享计数器的错误结果；再加上锁验证结果恢复正确。
  4. 选型分析 — 写一个简短报告（或注释），分别判断"批量图片压缩""高并发聊天服务器""日志文件逐行分析"三类任务该用进程、线程还是协程，并说明理由。
