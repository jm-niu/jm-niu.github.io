第二十二章：RESTful API 设计

难度：进阶 预计学习时间：1 周 前置知识：Web 开发、数据库、认证与安全

现代 Web 多采用前后端分离：后端只提供数据 API，前端（Vue/React/移动端）负责界面。本章讲解如何设计一套规范、好用、可维护的 RESTful API，包括资源建模、蓝图拆分、序列化校验、统一错误处理与文档生成，并说明前后端如何协作。

理解 RESTful 资源 用蓝图组织模块 序列化 + 统一错误 生成文档与协作

RESTful 理念

REST 的核心是把一切视为"资源"，用 URL 标识资源、用 HTTP 方法表达动作、用状态码表达结果。它让 API 直观、统一、可预测。

示意图：RESTful 路由约定 —— 同一个资源 /todos，用不同 HTTP 方法表达"查/增/取/删"，URL 名词化、方法动词化。

提示

常用状态码：200 成功、201 已创建、204 无内容（删除成功）、400 请求错误、401 未认证、403 无权限、404 不存在、422 校验失败、500 服务器错误。用对状态码，前端就能统一处理。

蓝图组织

项目变大后把所有路由塞在一个文件会失控。Flask 的蓝图（Blueprint）把相关路由分组到模块，便于管理和注册，类似前端的"路由模块化"。

Python
# todos.py — 待办蓝图
from flask import Blueprint, request, jsonify
from .models import db, Todo

bp = Blueprint("todos", __name__, url_prefix="/api/todos")

@bp.get("")
def list_todos():
    items = Todo.query.all()
    return jsonify([t.to_dict() for t in items])

@bp.post("")
def create_todo():
    data = request.get_json()
    t = Todo(task=data["task"])
    db.session.add(t); db.session.commit()
    return jsonify(t.to_dict()), 201

@bp.delete("/<int:tid>")
def delete_todo(tid):
    t = Todo.query.get_or_404(tid)
    db.session.delete(t); db.session.commit()
    return "", 204
Python
# app.py — 注册蓝图
from flask import Flask
from .models import db
from .todos import bp as todos_bp

def create_app():
    app = Flask(__name__)
    app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///todo.db"
    db.init_app(app)
    app.register_blueprint(todos_bp)        # 挂载 /api/todos
    return app
前端 JS/TS 类比：路由模块化

蓝图类似 Vue Router / Express Router 的"子路由模块"：把一组相关路由封装，再挂到主应用。前端用 router.use('/todos', todosRouter)，后端用 app.register_blueprint(todos_bp)，思路完全一致。

JavaScript
// Express 路由模块（与 Flask 蓝图同理）
const router = require("express").Router();
router.get("/", (req, res) => res.json([]));
router.post("/", (req, res) => res.status(201).json({}));
app.use("/api/todos", router);

序列化与校验

API 返回的 JSON 要序列化（对象 → dict → JSON），且不能把内部字段（如密码哈希）泄露出去；接收的输入要校验。用 marshmallow 或 pydantic 可规范完成。

Bash
pip install marshmallow
Python
from marshmallow import Schema, fields, validate

# 序列化 schema：定义对外字段与校验规则
class TodoSchema(Schema):
    id = fields.Int(dump_only=True)                       # 只输出
    task = fields.Str(required=True, validate=validate.Length(min=1, max=120))
    done = fields.Boolean(load_default=False)

todo_schema = TodoSchema()
todos_schema = TodoSchema(many=True)

# 输出：obj → dict
todo_schema.dump(todo_obj)
# 输入校验：dict → 校验后 dict，失败抛 ValidationError
todo_schema.load(request.get_json())

统一错误处理

好的 API 用统一的错误格式返回，便于前端解析与展示。Flask 用全局错误处理器把异常转成统一 JSON。

Python
from flask import Flask, jsonify
from werkzeug.exceptions import HTTPException
from marshmallow import ValidationError

app = Flask(__name__)

# 统一 HTTP 异常格式
@app.errorhandler(HTTPException)
def handle_http(e):
    return jsonify({"code": e.code, "msg": e.name, "detail": e.description}), e.code

# 校验失败 → 422
@app.errorhandler(ValidationError)
def handle_validation(e):
    return jsonify({"code": 422, "msg": "参数校验失败", "errors": e.messages}), 422

# 兜底：未捕获异常
@app.errorhandler(Exception)
def handle_all(e):
    app.logger.exception(e)
    return jsonify({"code": 500, "msg": "服务器内部错误"}), 500

API 文档

API 是给别的开发者用的，文档与接口同等重要。OpenAPI/Swagger 是事实标准，能自动生成交互式文档页，让人直接在浏览器里试调。

Bash
pip install flask-smorest    # Flask 的 OpenAPI 文档生成
Python
from flask_smorest import Api, Blueprint
api = Api(app, title="Todo API", version="v1")
# 用 @blp.doc(...) + Schema 装饰路由，自动生成 /swagger-ui 页面
# 访问 /api/swagger.json 看 OpenAPI 描述，/api/docs 看交互文档
项目案例：完整待办 API + 前端调用

把待办做成纯 API 服务，再用 Vue/原生 fetch 调用，实现前后端分离：

JavaScript
// 前端调用 RESTful API
async function loadTodos() {
  const res = await fetch("/api/todos", {
    headers: { Authorization: `Bearer ${token}` }
  });
  if (!res.ok) throw new Error("加载失败");
  return res.json();          // [{id, task, done}, ...]
}

async function addTodo(task) {
  const res = await fetch("/api/todos", {
    method: "POST",
    headers: { "Content-Type": "application/json", Authorization: `Bearer ${token}` },
    body: JSON.stringify({ task })
  });
  return res.json();          // 201 + 新建对象
}

后端只管数据与规则，前端只管界面与交互，两边通过 JSON 契约协作，互不耦合。

前后端协作

  • 约定契约

    先定 OpenAPI 文档（路径、字段、状态码），前后端据此并行开发，避免"你等我"。

  • 跨域 (CORS)

    前端与后端不同源时，后端要开启 CORS 允许跨域：flask-cors。

  • Mock 与联调

    后端未完成时，前端用 Mock 数据开发；接口就绪后切换真实地址联调。

  • 版本化

    URL 加版本前缀 /api/v1/todos，迭代时旧版仍可用，平滑迁移。

本章核心要点
  • REST：资源用 URL 名词，动作用 HTTP 方法，结果用状态码。
  • 用蓝图模块化路由，register_blueprint 挂载。
  • 序列化控制对外字段，校验拦截非法输入（marshmallow/pydantic）。
  • 统一错误格式 + 全局处理器，前端可一致处理。
  • 用 OpenAPI/Swagger 自动生成可交互文档。
  • 前后端分离靠 JSON 契约协作，注意 CORS 与版本化。

练习建议 动手实践

  1. REST 化 — 把待办网站改成纯 JSON API，用 GET/POST/DELETE 完成增删查。
  2. 蓝图拆分 — 把用户与待办拆成两个蓝图，各自独立文件。
  3. 校验+错误 — 接入 marshmallow 校验，统一错误返回 422。
  4. 文档 — 用 flask-smorest 生成 Swagger，在浏览器试调每个接口。
