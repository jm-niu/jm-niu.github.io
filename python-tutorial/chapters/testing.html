第十二章：调试与测试

难度：高级 预计学习时间：1 周 前置知识：函数、异常处理基础

写完代码只是第一步，确保它「正确」同样重要。本章介绍 Python 中常用的断言、调试与测试手段：assert 做开发期自检，logging / pdb 帮你定位问题，unittest 与 doctest 则把验证固化成可重复运行的测试。

断言 assert

assert 条件, "提示信息" 用于「程序在这里本应成立」的检查：条件为真时什么也不发生，为假时抛出 AssertionError。它适合开发期内部自检，例如函数前置条件。

Python 
def divide(a, b):
    assert b != 0, "除数不能为零"
    return a / b

print(divide(10, 2))   # 5.0
# print(divide(10, 0)) # AssertionError: 除数不能为零
注意

assert 会被 python -O 优化开关整体移除，因此不能用于运行期的数据校验（如用户输入合法性检查）。这类场景应主动抛出 ValueError / TypeError 等异常。

前端 JS/TS 类比：console.assert 与 assert 模块

Python 的 assert 对应 JS 的 console.assert 与 Node 内置的 assert 模块：都用于「期望条件成立，否则报错」，都属于开发期/测试期校验。

JavaScript 
// 浏览器 / Node 中的 console.assert
console.assert(2 + 2 === 4, "加法应该正确");
console.assert(1 > 2, "这条断言会失败");

// Node.js 内置 assert 模块
const assert = require("assert");
assert.strictEqual(10 / 2, 5);
// assert.strictEqual(1, "1"); // AssertionError

调试方法

当程序行为不符合预期，常用的调试手段从「随手打印」到「专业工具」依次递进：print 最快捷，logging 可分级持久化输出，pdb 则提供断点级的交互式单步调试。

Python 
import logging

# 1) print 大法：最快但难以关闭
def process(data):
    print("当前数据:", data)
    return data * 2

# 2) logging 分级：可控制级别、写文件
logging.basicConfig(level=logging.INFO)
logging.debug("调试信息（默认不显示）")
logging.info("程序启动")
logging.warning("内存占用偏高")

# 3) pdb 交互调试：在指定位置断住
def buggy(x):
    import pdb; pdb.set_trace()
    return x + 1
提示

pdb 常用命令：n 单步、s 步入函数、c 继续、p 变量 打印值、l 查看当前代码。Python 3.7+ 还支持更简洁的断点函数 breakpoint()。

前端 JS/TS 类比：debugger 与 DevTools

Python 的 pdb.set_trace() 相当于 JS 的 debugger 语句——在源码里插一个断点，运行到此处时由调试器（Chrome DevTools / VS Code）接管，可单步、查看变量、调用栈。

JavaScript 
function process(data) {
  debugger;            // 打开 DevTools 时在此断住，等价于 pdb.set_trace()
  console.log("当前数据:", data);
  return data * 2;
}
const x = 21;
console.log(process(x));  // 在 Sources 面板可逐步执行

单元测试 unittest

单元测试为「最小可测单元」（通常是函数）建立断言，保证改动不破坏既有行为。Python 标准库自带 unittest：用 TestCase 组织用例、assertEqual 等做断言、setUp 做前置准备。第三方库 pytest 则更简洁（不需要写类，直接用 assert）。

Python 
import unittest

def add(a, b):
    return a + b

class TestAdd(unittest.TestCase):
    def setUp(self):
        self.a = 2
        self.b = 3

    def test_add(self):
        self.assertEqual(add(self.a, self.b), 5)
        self.assertEqual(add(-1, 1), 0)

if __name__ == "__main__":
    unittest.main()


# 等效的 pytest 写法：函数 + 原生 assert，无需继承
def test_add_pytest():
    assert add(2, 3) == 5
    assert add(-1, 1) == 0
前端 JS/TS 类比：Jest / Vitest

Python 的 unittest / pytest 对应前端生态的 Jest / Vitest：都用 test()（或用例方法）+ 断言函数组织测试，setUp / beforeEach 做前置准备。

JavaScript 
// Jest / Vitest 写法，对应 Python 的 unittest
function add(a, b) { return a + b; }

test("两个数相加", () => {
  expect(add(2, 3)).toBe(5);
  expect(add(-1, 1)).toBe(0);
});

// 每个测试前的准备，对应 setUp
beforeEach(() => {
  // 初始化共享状态
});

文档测试 doctest

doctest 把「示例」直接写在函数的 docstring 里（用 >>> 模拟交互提示符），再统一执行并校验输出是否与文档一致。它让文档自动成为测试，既验证代码又保证示例不过时。

Python 
def multiply(a, b):
    """
    返回两数之积。

    >>> multiply(2, 3)
    6
    >>> multiply(-1, 5)
    -5
    """
    return a * b

if __name__ == "__main__":
    import doctest
    doctest.testmod()
提示

运行 python 文件名.py 时 doctest.testmod() 静默通过表示无误；加 -v 参数可看到每个示例的执行详情。docstring 里的 >>> 后写输入、下一行写期望输出即可。

前端 JS/TS 类比：JSDoc 示例即测试

Python 的 doctest 把示例嵌进文档字符串并自动校验；前端常用 JSDoc 的 @example 写可运行示例，再配合文档测试工具（如 doctest 类库）让示例保持可运行。

JavaScript 
/**
 * 返回两数之积。
 * @example
 * multiply(2, 3) // 6
 * multiply(-1, 5) // -5
 * @param {number} a
 * @param {number} b
 * @returns {number}
 */
function multiply(a, b) {
  return a * b;
}

练习建议 动手实践

  1. 给函数加 assert — 写一个计算阶乘的函数，用 assert 校验参数为非负整数，并故意传入负数观察 AssertionError。
  2. 写 pytest 测试 — 为上一步的阶乘函数编写 pytest 用例，覆盖正常输入、边界值（0! = 1）与异常输入。
  3. doctest 示例 — 给你常用的字符串处理函数加上 >>> 示例 docstring，运行 doctest.testmod() 验证示例正确。
  4. logging 配置 — 配置 logging 同时输出到控制台和文件，分别用 INFO / DEBUG 级别记录程序运行状态。
