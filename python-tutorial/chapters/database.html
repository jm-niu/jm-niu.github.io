第二十章：数据库与 ORM

难度：进阶 预计学习时间：1-2 周 前置知识：面向对象、Web 开发实战

上一章的待办清单用内存列表存数据——程序一关数据就没了，更无法多人共享。真实应用必须用数据库持久化数据。本章带你用 Python 生态最流行的 SQLAlchemy ORM，把上一章的待办网站升级为"数据不丢失"的真实应用，理解模型设计、CRUD、关系与迁移。

理解持久化与 ORM 用 SQLAlchemy 定义模型 掌握 CRUD 与查询 用迁移管理表结构

为什么需要数据库

变量存在内存里，进程结束即消失；文件能存盘但查询低效、并发难控。数据库把数据组织成"表（行×列）"，提供高效查询、事务、并发控制与持久化。关系型数据库（MySQL、PostgreSQL、SQLite）用 SQL 操作；非关系型（MongoDB、Redis）各有侧重。学习阶段用 SQLite 最方便——单文件、零配置，Python 标准库自带。

Python
# 标准库直接操作 SQLite（了解原理即可，实际项目用 ORM）
import sqlite3
conn = sqlite3.connect("todo.db")
cur = conn.cursor()
cur.execute("CREATE TABLE IF NOT EXISTS todo (id INTEGER PRIMARY KEY, task TEXT, done INTEGER)")
cur.execute("INSERT INTO todo (task, done) VALUES (?, ?)", ("学 Flask", 0))   # 参数化防注入
conn.commit()
for row in cur.execute("SELECT * FROM todo"):
    print(row)
conn.close()
注意

拼 SQL 字符串极易遭 SQL 注入攻击：f"... WHERE name='{name}'" 若 name 是 ' OR '1'='1 就会泄露全表。务必用参数化查询（? 占位符或 ORM），把用户输入当数据而非代码。

SQLAlchemy 与 ORM

直接写 SQL 字符串难以维护、易出错、与面向对象代码脱节。ORM（Object-Relational Mapping）把数据库表映射成 Python 类、行映射成对象，让你用 Todo.query.all() 代替 SELECT * FROM todo。SQLAlchemy 是 Python 最强大的 ORM，既支持高层 ORM 也支持底层 SQL 表达式。

示意图：ORM 映射关系 —— Python 的 Todo 类对应数据库 todo 表，类的每个实例对应一行记录，属性对应列。

前端 JS/TS 类比：ORM 与数据层

后端 ORM 类似前端的"数据访问层"：把存储细节封装起来，业务代码只面对对象。Node 生态的 Prisma/TypeORM/Sequelize 与 SQLAlchemy 同理——定义 schema、生成模型、用对象方法操作数据，框架自动生成 SQL。

JavaScript
// Prisma（Node ORM）写法，与 SQLAlchemy 思路一致
const todos = await prisma.todo.findMany({ where: { done: false } });
await prisma.todo.create({ data: { task: "学 ORM", done: false } });

模型设计

用 SQLAlchemy 定义模型，就是把"表结构"写成 Python 类。每个类属性 = 一个列，类型用 Column 声明。

Bash
pip install flask-sqlalchemy   # Flask 集成 SQLAlchemy 的封装
Python
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)
# SQLite 文件，数据持久化到 todo.db
app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///todo.db"
app.config["SQLALCHEMY_TRACK_MODIFICATIONS"] = False
db = SQLAlchemy(app)

# 定义模型 = 定义表
class Todo(db.Model):
    id = db.Column(db.Integer, primary_key=True)       # 主键
    task = db.Column(db.String(120), nullable=False)    # 非空字符串
    done = db.Column(db.Boolean, default=False)         # 默认 False
    created_at = db.Column(db.DateTime, server_default=db.func.now())

    def to_dict(self):
        return {"id": self.id, "task": self.task, "done": self.done}

# 首次运行时创建表
with app.app_context():
    db.create_all()
提示

db.create_all() 只在表不存在时创建，不会更新已存在表的结构。表结构变更要用迁移工具（如 Alembic/Flask-Migrate），见本章末尾。

增删改查 (CRUD)

CRUD 是数据操作的四大基本动作：Create 增、Read 查、Update 改、Delete 删。ORM 把它们变成直观的对象方法。

从零掌握 CRUD：4 个步骤

  • 创建（Create）

    new = Todo(task="学 ORM") → db.session.add(new) → db.session.commit()。记得提交，否则不落库。

  • 查询（Read）

    Todo.query.all() 全部、.get(id) 按主键、.filter_by(done=False).all() 条件查询。

  • 更新（Update）

    取出对象 → 改属性 → commit()。ORM 会自动生成 UPDATE 语句。

  • 删除（Delete）

    db.session.delete(obj) → commit()。删除前先确认对象存在。

Python
from app import app, db, Todo

with app.app_context():
    # 增
    t = Todo(task="完成数据库章节")
    db.session.add(t)
    db.session.commit()
    print("新增 id:", t.id)

    # 查
    all_todos = Todo.query.all()
    undone = Todo.query.filter_by(done=False).all()
    first = Todo.query.get(1)

    # 改
    first.done = True
    db.session.commit()

    # 删
    db.session.delete(first)
    db.session.commit()
项目案例：用数据库升级待办网站

把上一章的内存列表换成 SQLAlchemy，数据即可持久化、重启不丢：

Python
@app.route("/add", methods=["POST"])
def add():
    task = request.form.get("task", "").strip()
    if task:
        db.session.add(Todo(task=task))
        db.session.commit()
    return redirect(url_for("index"))

@app.route("/done/<int:todo_id>")
def done(todo_id):
    t = Todo.query.get_or_404(todo_id)   # 不存在返回 404
    t.done = not t.done
    db.session.commit()
    return redirect(url_for("index"))

get_or_404 是 Flask-SQLAlchemy 的便捷方法：找不到记录时直接返回 404 页面，避免手动判空。

关系与查询

真实数据往往有关联：一个用户有多条待办、一篇文章有多个评论。SQLAlchemy 用 relationship + 外键表达一对多关系，让你能 user.todos 直接拿到关联数据。

Python
class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(80), unique=True)
    todos = db.relationship("Todo", backref="user", lazy=True)

class Todo(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    task = db.Column(db.String(120), nullable=False)
    done = db.Column(db.Boolean, default=False)
    user_id = db.Column(db.Integer, db.ForeignKey("user.id"))   # 外键

# 使用
u = User(name="alice")
db.session.add(u); db.session.commit()
db.session.add(Todo(task="买牛奶", user_id=u.id)); db.session.commit()

print(u.todos)            # [Todo 1] — 直接拿到该用户所有待办
print(u.todos[0].user)    # 反向也能拿到所属用户 (backref)
提示

lazy=True 表示访问 user.todos 时才发 SQL 查询（懒加载）。若要一次性取出关联数据避免 N+1 查询问题，可用 joinedload 或 lazy="joined"。

数据库迁移

项目演进中表结构会变（加列、改类型）。直接改模型后 create_all 不会更新已存在表。迁移工具能记录每次结构变更，并能在不同环境间同步、回滚。Flask 生态用 Flask-Migrate（基于 Alembic）。

Bash
pip install flask-migrate

# 在 app.py 里：
# from flask_migrate import Migrate
# Migrate(app, db)

# 初始化迁移仓库（仅首次）
flask db init

# 每次改完模型后：
flask db migrate -m "add created_at to todo"   # 生成迁移脚本
flask db upgrade                                 # 应用到数据库
flask db downgrade                               # 回滚上一步
注意

迁移脚本提交进版本库，团队成员拉代码后执行 flask db upgrade 即可同步结构。生产环境迁移前务必备份并先在测试库演练，因为某些结构变更（如删列）会丢数据且不可逆。

本章核心要点
  • 数据库持久化数据；学习用 SQLite，生产用 MySQL/PostgreSQL。
  • SQL 注入是头号威胁——永远用参数化或 ORM，禁止拼字符串。
  • ORM 把表映射成类、行映射成对象，SQLAlchemy 是 Python 主流。
  • CRUD 四动作：add+commit、query.filter、改属性+commit、delete+commit。
  • 关系用 relationship + ForeignKey，注意 N+1 查询问题。
  • 表结构变更用 Flask-Migrate 迁移，提交脚本团队同步。

练习建议 动手实践

  1. 持久化待办 — 把上一章的待办网站改成 SQLAlchemy 存储，重启后数据仍在。
  2. 多用户 — 增加 User 模型与一对多关系，每个用户有自己的待办列表。
  3. 查询练习 — 写出"未完成且按创建时间倒序前 10 条"的查询。
  4. 迁移演练 — 给 Todo 加 priority 列，用 Flask-Migrate 生成并应用迁移。
