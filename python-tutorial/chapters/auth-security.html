第二十一章：用户认证与 Web 安全

难度：进阶 预计学习时间：1 周 前置知识：Web 开发、数据库与 ORM

有了 Web 框架和数据库，下一步必须解决"谁在用、能不能用"——这就是认证（Authentication，确认身份）与授权（Authorization，确认权限）。同时，Web 是公开暴露的服务，安全漏洞（XSS、CSRF、注入）随时可能被利用。本章把上一章的待办应用加上"用户登录"，并系统讲解常见 Web 攻击与防护。

密码哈希（不可逆） Session/JWT 登录态 XSS / CSRF 防护 安全最佳实践

密码哈希

绝对不要明文存密码。一旦数据库泄露，所有用户密码暴露，且用户常在多站复用密码，后果灾难性。正确做法是用加盐哈希：把密码经单向函数变成不可逆的固定长度串，并加入随机"盐"防止彩虹表攻击。

Python
from werkzeug.security import generate_password_hash, check_password_hash

# 注册时：存哈希，不存明文
raw_pwd = "my-secret-123"
hashed = generate_password_hash(raw_pwd)   # 自动加盐，如 pbkdf2:sha256:...
print(hashed)        # 每次结果不同（盐随机）

# 登录时：用 check_password_hash 验证
print(check_password_hash(hashed, "my-secret-123"))  # True
print(check_password_hash(hashed, "wrong"))            # False
注意

不要用 MD5/SHA1 存密码——它们太快，易被暴力破解。推荐 bcrypt、argon2 或 Werkzeug 内置的 pbkdf2，它们故意"慢"，并自带盐。也不要自己发明哈希算法。

前端 JS/TS 类比：前端密码处理

前端可以在提交前做一次哈希，但不能替代服务端哈希——前端代码可被篡改、绕过。Node 生态用 bcrypt/argon2 同样在服务端哈希。前端只负责 HTTPS 传输与基础校验。

JavaScript
// Node 端用 bcryptjs（与 Python 思路一致）
const bcrypt = require("bcryptjs");
const hash = await bcrypt.hash("my-secret-123", 10);  // 10 = cost
await bcrypt.compare("my-secret-123", hash);          // true

Session 与登录态

HTTP 是无状态协议——服务器记不住"上一个请求是谁发的"。登录态靠 Session 实现：用户登录后，服务器生成一个会话 ID 存在内存/数据库，并通过 Cookie 发给浏览器；后续请求浏览器带上 Cookie，服务器据此识别用户。

示意图：Session 登录流程 —— 首次登录服务器发 Cookie，之后浏览器自动带上，服务器据此维持登录态。

Python
from flask import Flask, request, session, redirect, url_for, render_template
from flask_sqlalchemy import SQLAlchemy
from werkzeug.security import generate_password_hash, check_password_hash

app = Flask(__name__)
app.secret_key = "a-very-secret-random-string"   # 用于签名 Session，必须保密
db = SQLAlchemy(app)

class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(80), unique=True)
    pwd_hash = db.Column(db.String(200))

@app.route("/register", methods=["GET", "POST"])
def register():
    if request.method == "POST":
        name = request.form["name"].strip()
        if User.query.filter_by(name=name).first():
            return "用户名已存在"
        u = User(name=name, pwd_hash=generate_password_hash(request.form["password"]))
        db.session.add(u); db.session.commit()
        return redirect(url_for("login"))
    return render_template("register.html")

@app.route("/login", methods=["GET", "POST"])
def login():
    if request.method == "POST":
        u = User.query.filter_by(name=request.form["name"]).first()
        if u and check_password_hash(u.pwd_hash, request.form["password"]):
            session["user_id"] = u.id        # 登录态写入 session
            return redirect(url_for("profile"))
        return "用户名或密码错误"
    return render_template("login.html")

@app.route("/profile")
def profile():
    uid = session.get("user_id")
    if not uid:
        return redirect(url_for("login"))    # 未登录踢回登录页
    return f"欢迎用户 #{uid}"

@app.route("/logout")
def logout():
    session.pop("user_id", None)
    return redirect(url_for("login"))

JWT 认证

Session 把状态存在服务端，扩展到多台服务器时需共享 Session 存储。JWT（JSON Web Token）把登录态直接编码在 Token 里发给客户端，服务端无状态，适合前后端分离与微服务。Token 由 Header.Payload.Signature 三段组成，签名保证不可篡改。

Bash
pip install pyjwt
Python
import jwt, datetime

SECRET = "change-me-in-production"

def make_token(user_id):
    payload = {
        "uid": user_id,
        "exp": datetime.datetime.utcnow() + datetime.timedelta(hours=2)   # 2小时过期
    }
    return jwt.encode(payload, SECRET, algorithm="HS256")

def verify_token(token):
    try:
        return jwt.decode(token, SECRET, algorithms=["HS256"])   # 验签+查过期
    except jwt.ExpiredSignatureError:
        return None      # 过期
    except jwt.InvalidTokenError:
        return None      # 非法

# 使用
token = make_token(42)
print(token)                    # eyJhbGci...
print(verify_token(token))      # {'uid': 42, 'exp': ...}
注意

JWT 签名只保证不被篡改，不保证不被窃取。Token 一旦泄露，在过期前可被冒用。务必走 HTTPS、设置较短过期时间、敏感操作二次验证。Token 不要存 localStorage（易被 XSS 偷），优先用 HttpOnly Cookie。

XSS 防护

XSS（跨站脚本）指攻击者把恶意脚本注入到页面里，在其他用户浏览器执行，从而偷 Cookie 或劫持操作。根源是"未转义的用户输入被当作 HTML 渲染"。Jinja2 默认对 {{ }} 自动转义，是第一道防线。

Python
# 假设用户输入了： <script>alert(document.cookie)</script>
name = "<script>alert(document.cookie)</script>"

# Jinja2 默认转义，安全：
# {{ name }} 渲染成 &lt;script&gt;...（显示为文本，不会执行）

# 危险：用 |safe 或 Markup 关闭转义，等于主动放行 —— 慎用！
# {{ name | safe }}   ← 这样会真的执行脚本！
提示

凡是把用户输入渲染进 HTML，都依赖自动转义。需要输出富文本时，用白名单过滤库（如 bleach）只放行安全标签，而不是关闭转义。Cookie 加 HttpOnly 标志可让 JS 读不到，进一步降低 XSS 危害。

CSRF 防护

CSRF（跨站请求伪造）指用户已登录 A 站时，被诱导访问恶意 B 站，B 站偷偷向 A 发请求（浏览器自动带上 A 的 Cookie），冒充用户执行操作。防护核心是给表单加一个攻击者无法预测的随机 Token。

Python
# 用 Flask-WTF 自动处理 CSRF Token
pip install flask-wtf

# app.py
from flask_wtf import FlaskForm, CSRFProtect
from wtforms import StringField, PasswordField
from wtforms.validators import DataRequired

app.config["SECRET_KEY"] = "your-secret"
CSRFProtect(app)   # 全局开启 CSRF 保护

class LoginForm(FlaskForm):
    name = StringField("用户名", validators=[DataRequired()])
    password = PasswordField("密码", validators=[DataRequired()])

项目案例：给待办网站加登录与防护

综合本章：注册用哈希、登录写 Session、表单加 CSRF、模板靠自动转义防 XSS，并要求登录后才能操作待办：

Python
from functools import wraps

def login_required(f):
    @wraps(f)
    def wrapper(*args, **kwargs):
        if "user_id" not in session:
            return redirect(url_for("login"))
        return f(*args, **kwargs)
    return wrapper

@app.route("/add", methods=["POST"])
@login_required                       # 未登录先去登录
def add():
    task = request.form.get("task", "").strip()
    if task:
        db.session.add(Todo(task=task, user_id=session["user_id"]))
        db.session.commit()
    return redirect(url_for("index"))

这样每个用户只能看到自己的待办，且所有写操作都受 CSRF Token 与登录态双重保护。

安全最佳实践

  • 密码加盐哈希

    用 bcrypt/argon2/pbkdf2，绝不明文存密码，绝不自己造哈希。

  • 防注入

    所有数据库操作走 ORM 或参数化查询，禁止字符串拼接 SQL。

  • 防 XSS / CSRF

    依赖模板自动转义、给表单加 CSRF Token、Cookie 设 HttpOnly + SameSite。

  • 最小权限与日志

    数据库账号只给必要权限；记录访问日志便于审计与溯源。

  • HTTPS 与密钥管理

    全站 HTTPS；密钥与口令放环境变量，不入代码库，定期轮换。

本章核心要点
  • 认证确认"你是谁"，授权确认"你能做什么"，二者不同。
  • 密码加盐哈希存储，用慢哈希算法，绝不明文。
  • Session 把状态存服务端；JWT 把状态存客户端，适合无状态/前后端分离。
  • XSS 靠模板自动转义防；CSRF 靠Token防。
  • SQL 注入靠ORM/参数化根除。
  • 全站 HTTPS、密钥入环境变量、最小权限、记录日志。

练习建议 动手实践

  1. 注册登录 — 给待办网站加注册/登录/登出，密码用哈希存储。
  2. 登录保护 — 用 login_required 装饰器保护待办操作，未登录跳登录页。
  3. JWT 版 — 把 Session 改成 JWT，写一个受保护 API 接口，用 Token 访问。
  4. 安全加固 — 接入 Flask-WTF 的 CSRF，测试表单没有 Token 时是否被拒。
